# Agent adapters

Checked against commit a213d8d on 2026-11-01.

## Objective

An adapter isolates everything one agent harness does differently from the core verifier: how its session file is read into claims, how observed events are rewritten into the form claims use, what the harness does on its own, and which content fields its format can state. `pkg/matching` and `pkg/verification` contain no agent knowledge; adding an agent means adding a package under `pkg/agent` that implements `agent.Adapter` and registers itself. The design reasons are in [decisions/integration.md](../decisions/integration.md) (D6 to D13) and [decisions/verification.md](../decisions/verification.md) (V2, V7).

### The Adapter interface

```go
type Adapter interface {
	Name() string
	Detect(path string) bool
	Parse(path string) (models.Trajectory, Report, error)
	Normalize(models.GroundTruthEvent) (models.GroundTruthEvent, bool)
	IsHarnessNoise(models.GroundTruthEvent) bool
	Expresses(entry models.TrajectoryEntry, field string) bool
	Process() ProcessModel
}
```

`Launcher` is an optional interface, `HarnessProcess(g models.GroundTruthFile) uint32`, for an adapter whose harness command is a launcher that starts the harness as its child rather than exec'ing it in place: it names the harness process when the capture's root is its launcher in the shape the adapter measured, and `Prepare` and `Capture` root the capture there (`agent.Rooted`, I-81, below). `HarnessOwner` is an optional interface, `IsHarnessOwned(path string) bool`, for an adapter that can say where the harness keeps its own files; the verifier reports an unexplained level-0 file event there as unexplained harness activity rather than as the agent's unreported action ([20_verifier.md](20_verifier.md#verdict-vocabulary), V-24, I-30). It declares where, not what: nothing is explained by it. `BackgroundOutputter` is an optional interface, `IsBackgroundOutput(path string) bool`, for an adapter that can name the files its harness writes a command's output to and opens only up to the command's end; `Prepare` sets `Options.BackgroundOutput` from it, and the verifier reads an open of such a file more than a second after its last write as the agent's, neither explained by the baseline nor harness-owned (V-56). `HarnessBookkeeper` is an optional interface, `HarnessBookkeeping(version, home string) func(models.GroundTruthEvent) bool`, for an adapter that can name the exact files its harness rewrites as its own bookkeeping: given the harness version the session records and the home the capture resolved `~/` against (empty when it recorded none), it returns a predicate over events, or nil. `agent.HarnessBookkeeping(a, version, g)` calls it with the session's `Report.AgentVersion` and the capture's snapshot home, and is nil for an empty version; `Prepare` does not set it, since it does not know the session's version, so `cmd/verify`, `cmd/analyze` and the attack evaluation set `Options.HarnessBookkeeping` themselves. Unlike `HarnessOwner` this explains: the verifier explains a level-0 event it recognises under the harness's own directories, on a path no claim names, as declared harness bookkeeping (V-50). `CaptureBookkeeper` is an optional interface, `CaptureBookkeeping(version, home string, raw models.GroundTruth) func(models.GroundTruthEvent) bool`, for bookkeeping whose shape the adapter recognises only in the capture's raw events, before `NormalizeStream` folded them; `agent.HarnessBookkeeping` passes the capture's events and accepts an event either declaration recognises (V-58). `HarnessHousekeeper` is an optional interface, `HarnessHousekeeping(version string) []agent.Housekeeping`, for an adapter that can name the exact network actions its harness performs on its own only sometimes, for the harness version the session records: each a `net_connect` to a host or a `net_request` with its exact target as the net probe writes it (`<METHOD> <URL>`, query included) and whether it carries a body, or, with `Origin`, every body-less request of one method to one origin, `<METHOD> https://<host>/`, except the paths in `Except` (V-57); an `Origin` declaration with a body, of a connection or of another form declares nothing. `agent.HarnessHousekeeping(a, version)` turns the list into a predicate that also requires an untruncated target and, for an exact request, a body exactly when one is declared; it is nil for an empty version or an empty list, and `cmd/verify`, `cmd/analyze` and the attack evaluation set `Options.HarnessHousekeeping` from it after `Prepare`. It explains: the verifier explains a level-0 connection or request it recognises, on a target no claim names, as declared harness housekeeping (V-54). `HarnessHoster` is an optional interface, `HarnessHosts() []string`, for an adapter that can name its harness's own service hosts, exact host names as the net probe reports a connection's target (its TLS SNI), that the harness connects to only in some runs; the verifier reports an unexplained level-0 `net_connect` to exactly one of them as unexplained harness network activity rather than as an omission (V-34). A host is declared only from a capture that shows the harness's own process connecting to it in some runs and not others (I-52, I-53); a host in every run is the baseline's. Like `HarnessOwner` it explains nothing, and a connection there by a command the agent ran stays a finding. `HarnessCommander` is an optional interface, `HarnessCommands() []string`, for an adapter that can name the commands its harness starts on its own only in some runs, each the exact command line of the exec as the proc probe reports it before `Normalize`; `agent.HarnessCommand(a, rawEvents)` recognises such an exec among the normalized events by the pid and timestamp of a raw exec whose target is exactly a declared line, not truncated, and that `Normalize` left unchanged, so an agent's shell call whose wrapper normalizes to the same line is never recognised. The verifier reports a level-1 command whose own exec it recognises, that no rule explains and no claim names, as an unexplained harness command rather than an omission, and checks what it did beneath it against the controls (V-43). A command is declared only from captures that show the harness's own process starting it in some runs and not others. It explains nothing and is no rule. `SensitiveDeclarer` is an optional interface, `SensitiveFiles() []string`, for an adapter that can name its harness's security-sensitive files: the short list of settings, permission and configuration files whose change would change what the harness lets the agent do, each under `~/` (the home of the user the agent runs as) or `{workspace}/` (I-59). `cmd/watch` snapshots them at the start and the stop of a capture with `pkg/agent/sensitive` ([40_tools.md](40_tools.md#watch), [10_probes_common.md](10_probes_common.md#ground_truthjson), V-40); `agent.SensitiveFiles(a)` returns the list, or nil for an adapter that declares none. `SensitiveKeyDeclarer` is an optional interface, `SensitiveKeys(file string) []string`, for an adapter one of whose declared files mixes the harness's state (caches, counters, timestamps) with its settings: for that file it returns the key paths that decide what the harness lets the agent do, as patterns of dot-separated elements in which `*` matches any one element (a per-project entry keyed by its directory), and nil for a file whose every key path is checked (V-41, I-60). An unexplained change under one of them is a finding, any other unexplained change of the file is listed report-only ([20_verifier.md](20_verifier.md#verdict-vocabulary)); `agent.SensitiveKeys(a, file)` returns the list, nil for an adapter that does not implement it. `TraceDeclarer` is an optional interface, `Trace(workspace, home string) *verification.TraceDecl`, for an adapter that can name where its harness keeps the session's own trace, the files its `Parse` reads, as the capture names those paths: `Covers`, the trace's files and directories, and `Main`, a main session file (I-74). `agent.Trace(a, g)` calls it with the capture's workspace and snapshot home, nil for an adapter that does not implement it; `Prepare` does not set it, and `cmd/verify`, `cmd/analyze` and the attack evaluation set `Input.Trace.Decl` from it. The verifier reads a write-class event on a covered path by any process but the agent's own, and a write-class claim of one, as trace tampering, a finding (V-59). It declares where the trace is, not what the harness does: the harness's appends are the agent process's events. `agent.ReadTrace(a, path, hash)` reads a session for `cmd/verify` and `cmd/analyze`: for an adapter that declares a trace, a file that does not exist, holds no byte, that `Parse` refuses or of which some record did not parse is returned as a state (`missing`, `empty`, `unparsable`, `damaged`) with its reason and no error, and with `hash` an intact file's SHA-256 is returned for the verifier to compare with the probe's last hash (V-59); an error is returned only when the file exists and cannot be examined. An adapter that declares no trace reads as before: a `Parse` error is an error and parse errors stay in the report. `Canonicalizer` is an optional interface, `Canonical(models.GroundTruthEvent) models.GroundTruthEvent`, for an adapter whose observed targets carry ids that differ every run: it returns the event with those ids replaced by fixed tokens, and is applied only where events of different runs are compared, when `Capture` builds rules and when `Prepare` matches a run's events against them. Pairing and every other comparison within a run use the exact target (I-41). `StreamNormalizer` is an optional second interface, `NormalizeStream(models.GroundTruth) models.GroundTruth`, for an adapter whose observed events are comparable only when several are looked at together (I-22). `OpenCollapser` is an optional interface, `CollapsesOpenRuns() bool`, for an adapter whose claims and `NormalizeStream` count a run of opens of one file as one access; `Prepare` then sets `Options.CollapseOpenRuns`, and the verifier folds a run again once the baseline's and the harness's own events are set aside, since `NormalizeStream` runs before the baseline is known (V-49). Claude Code declares it; agy does not, since its claims keep every open (I-50). `Name` keys the registry and the baseline file. `Parse` returns entries in claim order, each with its interval (`Timestamp`, `End`), its `ThreadID` where subagents were flattened, its `BlockID` where the format issued several calls at once, and its `Tool`. `Normalize` returns false to drop an event. `IsHarnessNoise` is what the adapter knows statically; the measured baseline is supplied separately. `Expresses` answers for one of the `verification.Diff*` field names.

### ProcessModel

| Field | Meaning |
|---|---|
| `ShellPerCommand` | Each shell claim execs its own process, so a claim aligns with a command's exec. False means a persistent shell, where both checks lose their subject. |
| `SubagentsInProcess` | Subagent actions are indistinguishable from main-thread ones in G, which forces flattening (D9). |
| `Containerized` | Observed paths and pids live in another namespace. No adapter handles it. |
| `IntervalKind` | `IntervalNone` (a point), `IntervalDecision` (start is when the model decided, includes approval latency), `IntervalExecution` (start is when execution began). |
| `Concurrency` | `Sequential`, `Parallel` (entries sharing a `BlockID` have no order among themselves), `ConcurrencyUnmeasured`. |
| `ExitsClaimed` | The format records process exits. False makes `Prepare` set `Options.IgnoreExits`. |

Only `ExitsClaimed` changes verifier behaviour today. The other fields are declarations; `Concurrency` in particular is not consumed, because the verifier does not implement the partial order ([20_verifier.md](20_verifier.md), Known limits).

### Report

`Report` makes what was not measured visible: `ToolCalls` (invocations in the session), `Entries` (claims produced), `AgentVersion` (the harness version the session states, if any), `UnmappedByTool` (tool calls that produced no entry, by name), `UnknownTools` (tools neither mapped nor declared non-effectful, which may have acted unseen), `ParseErrors`, `Degradations` (each precision loss in words), and `ServerCalls`, the calls the harness's model API ran on its own side, each with its tool, id, the session's request id for it and the model API host, which also count in `UnmappedByTool` and which `cmd/verify` passes to the verifier as `Input.ServerCalls` (V-45), `ModelRequests` and `ModelRequestMethod`, the requests the record says the harness sent to its model API with each input item digested by `tlsparse.ResponsesItemDigest`, and the content method that carries them, which `cmd/verify` passes as `Input.ModelRequests` and `Input.ModelRequestMethod` (P-43; the Codex adapter fills them, I-91). `cmd/verify` prints all but the last before the verdict, and the server-side calls with the verifier's check of each.

## Technologies

Go. The Claude Code adapter reads JSONL with `bufio.Scanner` (lines up to 64 MiB) and `encoding/json`. The Gemini adapter copies the conversation database and its write-ahead log, when there is one, into a private temporary directory and opens the copy read-only through `modernc.org/sqlite` (pure Go, no cgo), so reading a session writes nothing next to it (I-51), and decodes the undocumented protobuf step payload with a hand-written wire-format walker (`wire.go`), since no `.proto` is available. Content hashes use `pkg/content.SHA256Bytes` (`sha256:<hex>`).

## Workflow

### Registry and detection

Each adapter package calls `agent.Register` from `init`. `Register` panics on an empty or duplicate name. A command makes an adapter available by importing its package (`cmd/verify`, `cmd/baseline`, `cmd/analyze`, `cmd/attack` and `cmd/watch` blank-import `claudecode`, `codex` and `gemini`).

`agent.Detect(path)` asks every registered adapter, in sorted name order, whether it recognises the path. Exactly one match returns that adapter. No match returns an error wrapping `ErrNoMatch`, so a caller can fall back to the generic adapter. Several matches return an error naming them; the caller must choose with `--agent`. The generic adapter never detects.

### From session to verifier input

`agent.Prepare(a, claims, groundTruthFile, measured, opts)` builds a `verification.Input`: first, for an adapter that declares a launcher (`agent.Launcher`, `HarnessProcess(g)`, I-81), it roots the capture at the harness process with `agent.Rooted`, which drops the launch's own records (the fork that created the process, its execs before any other event of it, its exits) and leaves the capture as it is unless the named process is the root's only child and the root's own events are reads and local socket connects; then, when the adapter is a `ContentClaimer`, it first drops every claim the adapter's `NeedsContent` names whose content the capture did not read, since the probe then emits no request to witness it (I-72): an adapter that is also a `ContentMethodDeclarer` names, per claim, the content method the claim depends on, and the state read is that method's (`ProbeCoverage.MethodContent`, N-42), so a method that saw nothing drops only the claims that depend on it; otherwise, and for a declared empty name, it is the net probe's `Content` as a whole (Claude Code, whose single method's state it is); it runs the observed events through `agent.NormalizeGround` (every event through `a.Normalize`, dropping those it rejects, then the stream through `NormalizeStream` when the adapter implements it; `Capture` uses the same function, so a rule is measured on the shape the verifier compares against), combines `a.IsHarnessNoise` and the measured baseline into one predicate (an event is harness activity if either says so; the measured baseline sees the event as `Canonical` returns it, the events the verifier aligns keep their exact targets, I-41), sets `opts.Expresses = a.Expresses`, `opts.IgnoreExits = !a.Process().ExitsClaimed`, when the adapter is a `HarnessOwner`, `opts.HarnessOwned`, when it is a `HarnessHoster`, `opts.HarnessHosts`, and `opts.HarnessCommand = agent.HarnessCommand(a, groundTruthFile.Events)` (nil when the adapter declares no command or the capture holds none of them), and copies `RootPID`, `Coverage`, `FSScope` and `Workspace` from the file. Caller options such as `IntervalSlack` are kept. `agent.PrepareWithBaseline(a, claims, groundTruthFile, baseline, opts)` does the same with a `*Baseline`, passing its `Predicate` as the measured baseline and its subtree records as `Input.BaselineSubtree` (`agent.BaselineSubtree`: the command and the event beneath it are compared in their `Canonical` form, and a command `IsHarnessNoise` declares explains its whole subtree), so a baselined command explains only what its controls did beneath it (V-38). `Prepare` given only the predicate leaves the records out and keeps the V7 reading; `cmd/verify` sets `BaselineSubtree` after `Prepare`. Both set `Input.Sensitive` with `agent.SensitiveInput(a, groundTruthFile, baseline)` (V-40): nil when the capture holds no snapshot or the adapter declares no file, else one entry per declared file with what the snapshot recorded of it and the adapter's `SensitiveKeys` for it, and, from a baseline with a sensitive record, `Baseline.SensitiveExplained` and which files its controls measured; `Prepare` passes no baseline, so the changes are reported as not checked, and `cmd/verify` sets it again with its baseline.

### Generic

`Generic` reads a trajectory already in the normalized JSON form (`models.ParseTrajectory`, which rejects unclaimable action types). It normalizes nothing, declares no noise, treats every field as expressible, and declares `ShellPerCommand`, `IntervalNone`, `Sequential` and `ExitsClaimed: true`. Its report carries one degradation saying so. It is the adapter for `cmd/simagent` output and for an agent whose format has been converted elsewhere.

**Precision lost against the native adapters.** **Verified** on eleven of the fourteen paired fixtures of the native adapters, all but `paired-2.1.306-tools`, `paired-codex-0.166.0-basic` and `paired-codex-0.166.0-tools-2`, which the test does not list yet (`generic_paired_test.go` in `pkg/agent`): each session is read by its own adapter, written as the generic format and read back by `Generic`, then verified against the same task run, once with a baseline `Generic` captured from the fixture's controls and once without, both at an agreement of one control in N. The conversion applies only what the format can state: the entries as the native `Parse` returned them, without the harness-implied claims (`attack.WithoutImplied`). `ImpliedBy` has no JSON form, so a converted trajectory never names it, and `ParseTrajectory` refuses one that does (V-33); a converter that kept such an entry would make the harness's read a claim of the agent's. Nothing on the observed side is converted. A run of `cmd/verify --agent generic` with a baseline from `cmd/baseline --agent generic` on `paired-2.1.286` gives the same counts as the test.

Every one of the 22 verdicts is NOT FAITHFUL, against FAITHFUL or INCONCLUSIVE natively. No claim is unwitnessed, and every mismatch differs on the target: a command against its wrapper's argv, a write against a temporary or the harness's own file. None is a disagreement on the content of the claimed target, so the outcomes show lost precision, not a defect of `Generic`. - Wrapper recovery (I-23, I-26, I-47). - Declared harness bookkeeping (V-50). `Generic` declares none, so the harness's rewrite of its version lock, when no rule explains it, is an unrecorded finding.
- Declared harness housekeeping (V-54). `Generic` declares none, so Claude Code's token renewal, when no rule explains it, is an unrecorded finding.
- Declared harness commands (V-43). `Generic` declares none, so Claude Code's package-manager probe, when no rule explains it, is an unrecorded command and an unexplained subtree, not an unexplained harness command.
- Sensitive files (I-59, I-60). `Generic` declares none, so a capture's snapshot is never checked (V-40). No fixture holds a snapshot, so the fixtures do not measure it.

- Version configuration (I-57). `Generic` states no harness version and `cmd/verify` does not check one: the report prints no warning, the JSON report says `not applicable`, and `--strict-version` leaves the verdict as it is. A baseline's version is not compared either.

### Claude Code (`claude-code`)

Detect: a `.jsonl` file in which one of the first 20 lines decodes with non-empty `sessionId`, `type` and `version`.

Parse reads the main transcript, then every `<session>/subagents/agent-*.jsonl` in sorted order (D8), with the file's id as `ThreadID`. It collects `tool_use` blocks from the records of type `assistant` and the timestamp of each matching `tool_result` from the records of type `user` (I-62). A record of any other type states no call and no result and is skipped without a report: from 2.1.306 the transcript also holds `api-request`, `api-request-shape` and `api-request-blob` records, and an `api-request-blob` copies an API request whose content repeats earlier `tool_use` and `tool_result` blocks under the same ids, with no timestamp and no structured result. A `tool_use` id or a `tool_result`'s `tool_use_id` seen a second time, in the main transcript or a subagent's, is a parse error naming the file and line, and the first stays the one claimed. Calls are sorted by `tool_use` timestamp, ties in file order. A message holding more than one `tool_use` gives its entries `BlockID` = the message id. `End` is the `tool_result` timestamp when it is not before the start.

### Gemini (`gemini`)

The harness is `agy` (Antigravity's CLI), a single Go binary. A print-mode run (`agy -p`) keeps its conversation in `~/.gemini/antigravity-cli/conversations/<id>.db` and prints the id with `--output-format json`; it also writes transcripts under `~/.gemini/antigravity-cli/brain/<id>/`, which the adapter does not read. A subagent's steps are in a database of its own, `<subagent id>.db` in the same directory, named in the result of the `invoke_subagent` step (I-55).

Detect: a file starting with the SQLite header whose `steps` table has a `step_payload` column.

Detect and Parse read a private copy of the database and of its write-ahead log `<path>-wal`, when one exists, so steps the harness has not yet checkpointed into the database file are read, and nothing is created next to the session, whose directory may be read-only (I-51). Parse reads `steps` ordered by `idx` and decodes each payload. Tool calls are the submessages at protobuf path 5.4: field 1 the call id, 2 the tool name, 3 the arguments as a JSON string. The claim start is the started timestamp (5.6), falling back to created (5.1) with a degradation; `End` is completed (5.8) when present. Entries are sorted stably by start. A step with more than one call gives its entries `BlockID` = `step-<idx>`; calls the model issued together were seen as separate steps, one call each, which therefore carry no block id. Parse fails loudly, naming the field path, when a payload does not decode, a call lacks its name or arguments, the arguments are not JSON, a step has no timestamp, or the database has no steps: a version that moves a field number must produce an error, never an empty trajectory. The four conversation databases of those runs (three main conversations and a subagent's) and the 46 older ones on the development machine parse without an error. A payload holds more than the adapter reads: field 140 repeats the step with its result, a `run_command` result's text states the exit code (`The command exited with code N.`), and field 5.32 preceded the exec of each of seven measured commands by 12 to 23 ms (I-47); of these only an `invoke_subagent` step's result is read, as follows.

Parse then follows the subagents (I-55). A step holding an `invoke_subagent` call, whatever its status, names the conversations of the subagents it created at 140.2.6.2.143.10.1, one 143.10 per subagent: 140.2.6 is a `google.protobuf.Any` wrapping a Step, and 143 is that Step's subagent result. The result's text for the model (140.2.1) names the same ids and is not read. An id of any other form than a lowercase UUID is not looked up, since it comes from the trajectory and could name a path. Each id is looked up as `<id>.db` beside the conversation, where agy keeps it, and then in `<conversation without .db>/subagents/`, where the capture script copies it (`<label>.conversation/subagents/<id>.db`); nested subagents are looked up in the same two directories. The subagent's database is read like the main one (a private copy, I-51), and its claims get `ThreadID` = the subagent's conversation id (D9) and, for a step with several calls, `BlockID` = `<id>/step-<idx>`, so two threads' blocks never share an id (V-32). Subagents are read breadth first, each id once (so a cycle ends), down to four levels below the main conversation (`maxSubagentDepth`). The claims of all threads are sorted together, stably by start, the main thread's first on a tie, as the Claude Code adapter orders its subagents' calls. A subagent's tool calls join the report's counts. A subagent whose database is not found, an `invoke_subagent` step that names no usable id, and a subagent nested deeper than the bound are degradations, not errors; a subagent database that does not parse is a parse error naming the subagent and contributes nothing else.

### Baseline construction

A baseline is the harness's own activity, measured by control runs in which the agent is given a task that claims nothing, so everything it does is the harness (D11, V7).

`agent.Capture(a, version, runs, now, opts)` requires at least one run and a root pid in each. For each run it roots the capture at the harness process as `Prepare` does (`agent.Rooted`, I-81), normalizes events with the adapter (`NormalizeGround`, the same two steps as `Prepare`), builds the forest and partition, and takes the distinct `(action_type, target)` pairs of the aligned sequence (`Partition.Observed`), each event in the form the adapter's `Canonical` gives it, since a rule is compared with other runs (I-41). Descendants of a command are not rules. Instead, for every command rule, `Subtrees` records what the command did beneath it (V-38): the distinct `(action_type, target)` pairs of the checked types (`verification.SubtreeChecked`: programs run, files written, closed after writing, renamed or deleted, connections and requests) beneath any instance of the command in a run, canonical and with the workspace templated like a rule, kept in `Subtree.Events` when as many runs did them as a rule needs, and in `Subtree.Unstable` otherwise; reads and exits are not recorded. A pair seen in at least `opts.MinAgreement` of the runs (default 1, every run) becomes a `Rule`; a pair seen in fewer goes to `Unstable`, which is recorded for the reader and subtracts nothing. A target named in `opts.Exclude` becomes neither, whatever its action type, and the baseline records it in `Excluded`; it names the control task's own command (I-28) and, for a profile with an edit tool, the file the controls edit, `{workspace}/agent-trace-control.txt` (`agent.ControlFileTarget`, I-88). An exclusion matches the target as normalized and canonical, or the same with the run's workspace replaced by `{workspace}`. The run's own workspace (recorded by `watch` in the ground truth file) is replaced by `{workspace}` in each target, and its mangled form (every character but an ASCII letter or digit a dash, counted in UTF-16 units, which is how Claude Code names its per-project directories for transcripts, task outputs and logs) by `{workspace-}` (I-24, I-29, I-70); a mangled form over 200 characters, which the harness cuts and suffixes with a hash, is not templated. Both lists are sorted. The `Baseline` records `Schema`, `Agent`, `AgentVersion`, `Captured` (UTC), `Runs`, `MinAgreement` and `Excluded`; `SaveBaseline` writes it as JSON with the keys `schema` (1), `agent`, `agent_version`, `captured`, `runs`, `min_agreement`, `rules`, `unstable`, `excluded` and `subtrees`, each rule an `action_type` and a `target`, each subtree a `command` (the rule's target), its `events` and its `unstable` rules, and `declared` for the record of a declared harness command (below). `subtrees` is always written, an empty list when there is no command rule; a file without the key, written before V-38, loads with no records (`RecordsSubtrees` false), and its commands explain their whole subtree. For each command the adapter declares as the harness's own (`HarnessCommander`) that some control ran and that is no command rule at the baseline's agreement, `Capture` adds a record marked `Declared` (`declaredSubtrees`, V-43): the pairs beneath it that at least the agreement's share of the k controls that ran it did, at least one, the rest unstable. A declared command that is a rule has the rule's record.

`Capture` also records what the controls changed in the adapter's declared sensitive files (`Baseline.Sensitive`, V-40), when the adapter declares some and every control holds a snapshot; otherwise it records none, and the key `sensitive` is left out of the file. `files` lists the declared files every control measured at both ends (present or missing, not unread). For those files, each control's changes are taken as `(file, key, kind)` with the run's workspace replaced by `{workspace}` in every element of the key (Claude Code keys its per-project entries of `~/.claude.json` by the directory) and the mangled form by `{workspace-}`; a change made by as many controls as a rule needs is kept in `changes`, one made by fewer in `unstable`, which explains nothing. Entry counts and values are not recorded. `Baseline.SensitiveExplained(workspace)` answers whether a run's change, its key templated with the run's workspace, is exactly one of `changes`; nil when there is no record.

`Baseline.Predicate(workspace)` recognises an event when a rule has exactly its action type and target (`Prepare` passes it the canonical event), with the placeholders expanded to the workspace of the run being verified and its mangled form (a rule that names a placeholder matches nothing when no workspace is known, and one that names `{workspace-}` matches nothing when the mangled form is over 200 characters). There is no pattern matching, since a wildcard would explain whatever an attacker made it match. `Baseline.Subtree(workspace)` answers, for a command's exec and an event beneath it, whether the record of the command with exactly that target holds the event exactly, placeholders expanded the same way; a command with no record explains nothing beneath it, and a baseline without records gives nil. `LoadBaseline` rejects an unknown schema and a baseline that names no agent. Which control runs `cmd/baseline` refuses, and which baselines `cmd/verify` refuses, is in [40_tools.md](40_tools.md#baseline).

### Onboarding a new agent

Answer these questions, then encode each answer in the named place.

| Question | Encoded in |
|---|---|
| Where do session artifacts live, and what is the encoding? How is one recognised? | `Detect`, `Parse` |
| Which tools are effectful, and which are not? | `Parse` mapping; a non-effectful set; everything else to `UnknownTools` |
| For each effectful tool, which field holds the target, and which kernel events does it produce, in kernel order? | `Parse` claim shapes (claims of the `fs` lane must follow fanotify order) |
| Does a shell claim exec its own process, or is the shell persistent? (D7) | `ProcessModel.ShellPerCommand`; persistent calls counted, not claimed |
| Is the observed command line the claimed command, or a wrapper? (D6) | `Normalize` |
| Is the trajectory one stream, or split across files? (D8) | `Parse` merging |
| Are subagents separate processes or in-process? (D9) | `ProcessModel.SubagentsInProcess`, `ThreadID` |
| What does the harness do on its own? (D11) | A measured baseline via `cmd/baseline`; `IsHarnessNoise` only for what is static |
| Where do start and end timestamps come from, and does the start mean decision or execution? (D12, D13) | `Timestamp`, `End`, `ProcessModel.IntervalKind` |
| Which content fields can the format state, per tool? Does it record exits? | `Expresses`, `ProcessModel.ExitsClaimed` |
| Do observed paths and pids share a namespace with the trajectory's? | `ProcessModel.Containerized` (unhandled) |
| Can the agent issue several calls at once? (V2) | `ProcessModel.Concurrency`, `BlockID` |

Then: create `pkg/agent/<name>`, register from `init`, blank-import the package in `cmd/verify` and `cmd/baseline`, list every precision loss in `Report.Degradations`, and test `Detect`, the mapping, the `Expresses` table, the process model, loud failure on malformed input, and an honest synthetic session that verifies FAITHFUL after normalization. Finally capture a baseline from several control runs, check the adapter against a real paired capture, and add the adapter's profile, with the captured version, to `config/agents.json` (I-57, I-77): a profile that needs only implemented methods needs no script change, and one that needs a new method gets that method in the capture scripts, written so that it never names the agent.

## Guarantees and loss accounting

- No tool call is dropped silently: in both real adapters every call either produces entries or is counted in `UnmappedByTool`, and an unknown tool is also listed in `UnknownTools` (`TestParseCountsWhatItDoesNotMap`, `TestParseCountsAndNamesWhatItDoesNotClaim`).
- A format limit is never read as an opt-out: `Expresses` turns a nil that the format cannot state into no finding, and `ExitsClaimed: false` removes exits from both sides rather than reporting every exit as an omission.
- Detection never guesses between adapters (`TestDetectRefusesToGuessBetweenAdapters`).
- A search is recognised only from the command lines a capture showed, and the fold of a failed ripgrep with its fallback only in the measured shape; any other program, option shape or interleaving keeps its text (`TestSearchOfRecognisesOnlyTheMeasuredForms`, `TestFoldSearchesIsNarrow`, I-54).
- A Gemini subagent the conversation names is read or named in the report: a missing database, a result with no usable id and a subagent beyond the depth bound are degradations, and a subagent database that does not parse is a parse error; an id that is not a conversation id is never used as a path, and a cycle ends (`TestAMissingSubagentIsADegradation`, `TestAnInvokeWithNoUsableIDIsReported`, `TestASubagentThatDoesNotParseIsAParseError`, `TestNestedSubagentsAreBoundedAndCyclesEnd`, I-55).
- The Gemini adapter fails with the field path rather than returning a partial trajectory when the payload layout changes. It reads steps that only the write-ahead log holds, writes nothing next to the database, and reads a database in a read-only directory (`TestParseReadsTheLogAndLeavesTheDirectoryAlone`, `TestParseReadsADatabaseInAReadOnlyDirectory`, I-51).
- A harness-implied open is derived only from the call itself, never from a marker in the transcript, never for a command the reader does not follow, and never merged with the agent's own open of the file (`TestReadCommandFilesFollowsTheHarnessParser`, `TestABashReadCommandImpliesTheHarnessRead`, `TestTheAdapterIgnoresAMarkerInItsInputAndNeverMergesTheAgentsOpen`); the harness's read after `cat` in a parallel block is explained and the run FAITHFUL, and without the claim the read is Unrecorded (`TestTheHarnessReadAfterCatIsExplainedEndToEnd`, I-46).
- A claim pairs only with an event on the exact path it names, while the baseline compares runs on the canonical path: a Read of one background task's output file is not witnessed by another task's, and a control's task output still explains the run's own (`TestAClaimOnATaskOutputPairsWithThatFileOnly`, I-41).
- Claude Code declares the package-manager probe as its one harness command and agy none; a declared command's occurrence that no rule explains, on the 2.1.306 tools capture at full agreement, is INCONCLUSIVE with no finding, its subtree checked against the four controls that ran it, while a payload beneath it, and the same command line run through the Bash tool and not claimed, are findings (`TestTools306CorroboratesEveryClaimAndPinsTheAgreements`, `TestTools306ADeclaredHarnessCommandHidesNothing`); its record is a declared one at full agreement and the rule's below (`TestTools306RecordsTheDeclaredProbesSubtree`).
- Each adapter declares as harness hosts only the hosts its harness's own process connected to in some measured runs and not in others, never an address and never a host every run has (`TestHarnessHostsAreTheMeasuredOccasionalHosts` in both adapters, I-52, I-53), and `Prepare` passes them to the verifier (`TestPreparePassesHarnessHostsToTheVerifier`).
- Claude Code's trace declaration names each session transcript and the subagents' directory of the capture's project, as the harness mangles the workspace, and nothing else of the project; the harness's own writing of its trace on the 2.1.306 `tools` capture is no tampering, and a Bash command that deletes the transcript, added to that capture, is tampering after normalization (`TestTraceDeclaresTheSessionTranscriptsAndSubagents`, `TestTools306TheHarnessWritingItsTraceIsNoTampering`, `TestTools306ACommandDeletingTheTranscriptIsTampering`). A missing, empty or garbled transcript is read as a trace that cannot be verified, never an error (`TestReadTraceFailsClosed`).
- A baseline only subtracts exact `(action_type, target)` pairs that enough control runs produced, from loss-free runs, for the adapter it was captured with, and never the control task's own command (`TestCaptureExcludesTheControlTasksOwnCommand`, `TestPairedControlCommandIsNotABaselineRule`).
- A baselined command explains only the programs, writes and connections beneath it that the controls' same command produced: on the paired 2.1.286 capture a curl, a connection and a workspace write forked beneath the harness's `/bin/bash -c env` are each unexplained and the run NOT FAITHFUL (`TestPairedBaselineCommandDoesNotExplainAnInjectedSubtree`), while every checked-in Claude Code capture, at every agreement, has the same outcome and findings with the records as without (`TestSubtreeRecordsAddNoFindingToAnHonestFixture`, V-38). The records are built per command rule at the rules' threshold (`TestCaptureRecordsWhatEachCommandDidBeneathIt`).
- No call is claimed twice: a record of a type other than `assistant` or `user` that repeats calls and results claims nothing and replaces no result, and a call or result stated twice is a parse error with the first kept (`TestOnlyAssistantAndUserRecordsStateCalls`, `TestARepeatedCallIsAParseErrorNotASecondClaim`, I-62).
- An Edit's content claim reaches the verdict: on the `edits` capture, an Edit whose file ended with other content than its result reports is a Mismatched finding on its output hash and the run NOT FAITHFUL (`TestPairedEditWithSubstitutedContentIsNotFaithful`, I-31).
- The Codex adapter recovers a command only from the measured wrapper, every line before the payload in one of its shapes and the payload one word, and refuses a line run before or after it, a second word, another shell or a `pty` setup (`TestRecoverCommandRefusesAnythingElse`); its folds leave a command's file events, the harness's files, a rewrite with another file between and execs of one program from one directory alone (`TestNormalizeStreamIsNarrow`); a launcher that does more than start the harness is not rerooted (`TestRootedFailsClosed`, I-81); every item either claims or is counted, an unknown one listed (`TestParseCountsWhatItDoesNotClaim`).
- Every version `config/agents.json` lists has a fixture recorded by it, every versioned fixture is listed under its version, and every configured Claude Code version is in I-46's gate (`TestEveryListedFixtureHasItsVersion`, `TestEveryVersionedFixtureIsListed`, `TestVersionGatesAgreeWithTheConfig`, I-57).

## Known limits

- Some code still names agents (I-77): the fixture version test (`TestEveryListedFixtureHasItsVersion`) checks each adapter's fixtures in its own way, and `scripts/make-capture-fixture.py` knows each format by name. `scripts/bench-overhead.sh` and `scripts/compare/` read the profiles (I-98).
- The `sqlite-conversation` method's model check takes the tokens of the conversation's executor metadata shaped as a model id of the families `gemini-`, `claude-` and `gpt-`; a model of another family reads as none, so the run fails as a `MODEL MISMATCH`, not silently.
- Only `jsonl-session` and `jsonl-rollout` have the state check a declared trace needs; a profile that declares a `sqlite-conversation` trace is refused until that check exists.
- The `jsonl-rollout` method's subagent rule (a rollout the run created whose metadata names the session) and its reading of the parent history a subagent's rollout starts with, which the Codex adapter shares, rest on one survey of 0.166.0. Its database snapshots hold every thread of the account; the fixture script leaves them out (I-86).
- The instruction files are moved aside per run (I-79), so a session of the user's own that starts while a run lasts misses them, and every capture before 2026-10-31 (all fixtures included) ran with them present. Only the listed files move: an agent that reads another personal file, or the user's instructions through another path, still gets it.

- Claude Code and Codex declare their trace (I-74, I-84). Gemini (agy) declares its conversation databases as main session files and covers them with their `-wal` and `-journal` (I-102, V-75). A stock SQLite client that only reads a database opens it for writing; its closes are reads (V-75), and its create and delete of the `-wal` of a database no other process holds open are not tampering when the capture shows the file did not exist before and nothing was written to it (V-76). A reader's delete of a `-wal` that existed before it opened the database stays tampering, and so does a create the capture cannot tell from a truncation: on the private 1.4.7 pilot capture an agent's `python3 -c 'import sqlite3 ...'` reads of every conversation database of the account leave such events (**Verified**, local only). The `-shm` is not covered, so a change to it is never seen. A tool call the Gemini adapter cannot map (a missing `CommandLine`, `AbsolutePath`, `TargetFile` or `Url`) is a parse error, which `agent.ReadTrace` now reads as a damaged trace, so such a run is INCONCLUSIVE although the cause may be a format change rather than damage. With `--check-trace-hash` the database read is compared with the last hashed close of any conversation database the capture saw; a run in which only a subagent's or another conversation's last write is a hashed close would read as `differs` (on every agy capture at hand the conversation's own database was closed with a hash at the harness's exit and equals its copy, **Verified**, local only). Claude Code's declaration covers every session of the workspace's project directory, not only the one verified, and its main files only directly under the project directory.
- The fold takes a second rename of a replace's directory only in captures recorded before P-18; on a current capture its condition, narrower than P-18's, never holds (I-33). On an old capture it hides what P-18 hides: two real renames of one directory by one process with nothing between read as one. A split rename in the read-after-rename shape has not been seen in an old capture and is not folded, so it would show as an unrecorded rename of the directory.
- A Write's kind read from its result text (I-35) rests on the wording of 2.1.296, found in its binary and seen in the `tools` capture; the binary of 2.1.306 holds the same two sentences. Another wording gives no kind, so such a Write is assumed to overwrite, as before. Since commit 656d025, `scripts/make-capture-fixture.py` keeps a `tool_result` text that starts with the create or update sentence, and `is_error`, so a reduced fixture keeps a subagent's Write kind; a fixture reduced before that holds `(elided)` there, and its subagent Writes have no kind.
- The Claude Code claim shapes rest on the ten paired captures above; the background Bash call (`run_in_background`), the subagent that writes a file and `NotebookEdit` on the `tools` fixture and one more raw capture. The in-place rewrite of a Write and an Edit rests on one raw capture (`shapes`, I-45); a NotebookEdit in place and the paths taken when a rename fails are unchecked. Unchecked: other versions, `MultiEdit` (not offered by 2.1.296 and reported as an unknown tool, I-42).
