# Process probe

Checked against commit 077154f on 2026-10-20.

## Objective

The process probe (`pkg/probe/proc`) records which programs the agent's process tree ran, how they exited, and which process created which. It produces `process_exec`, `process_exit` and `process_fork` events carrying `PID` and `PPID`, so the verifier can rebuild the process forest from events alone and attribute every other probe's events through it. The common contract, clocks and coverage format are in [10_probes_common.md](10_probes_common.md).

## Structure

| File | Contents |
|---|---|
| `proc.bpf.c` | six programs, all raw tracepoints (P-32): `handle_fork` (`task_newtask`), `trace_sys_enter` (`sys_enter`, the syscall dispatcher, which handles `exit_group` itself), `handle_execve` and `handle_execveat` (tail-called by the dispatcher, both through `record_exec`), `handle_exec_ok` (`sched_process_exec`), `handle_exit` (`sched_process_exit`) |
| `observer.go` | `Config`, `Observer`, `New`, `procRawTracepoints`, `sysEnterPrograms`, `Start`, `Stop`, `drainRead`, `SetRootPID`, `CaptureCoverage`, `readLoop`, `joiner`, `commandLine` |
| `bpf_bpfel.go`, `bpf_bpfeb.go`, `.o` | generated by `bpf2go`, committed |

Kernel maps:

| Map | Type, size | Purpose |
|---|---|---|
| `tracked_pids` | hash, 16384 | tgid to `proc_info{is_shell, is_toplevel}` |
| `config_map` | array, 1 | 1 = ancestry-filtered mode, 0 = host-wide |
| `root_pid_map` | array, 1 | the root pid |
| `execs` | hash, 4096 | a header per tgid, written when an exec takes effect and kept until exit; the exit code lands here and the exit record is this header (P-19, P-31) |
| `heap` | array, one entry per possible CPU, sized at load | scratch `exec_scratch` (header, 256-byte filename, 256 KiB args area for a 128 KiB command line), indexed by the running CPU, which is private to `record_exec` because `sys_enter` runs it with preemption disabled; a per-CPU array value is capped at 32 KiB by the kernel |
| `sys_enter_progs` | program array, 2 | the dispatcher's tail-call slots: `handle_execve`, `handle_execveat` |
| `events` | ring buffer, 8 MiB | records to userspace; an exec record can be 128 KiB |
| `drop_count`, `untracked_count`, `state_lost_count` | per-CPU arrays | loss counters |

Record kinds (`event_hdr.kind`): `KIND_EXEC` 0 (an exec attempt), `KIND_EXIT` 1, `KIND_FORK` 2, `KIND_EXEC_OK` 3 (an attempt took effect). Only an exec record carries a filename and arguments; the others are the header only. The header's `tid` names the thread that made the attempt, in an exec and an exec-success record. The header's `args_truncated` says the filename or the arguments did not fit, or the probe could not read them to their end.

`Config` fields: `PIDFilter` (ancestry root set at `New`), `CommandFilter` (command line prefix), `DeferRootPID` (start filtered with an empty tracked set), `EventBufSize` (default 4096), and the test-only capacity overrides `RingbufBytes`, `TrackedPIDsMax` and `ExecsMax`.

## Technologies

eBPF raw tracepoints loaded with cilium/ebpf, one tail-call program array, one ring buffer, CO-RE (`BPF_CORE_READ`) to read `task_struct->real_parent->tgid`, the syscall arguments from the saved user registers (`pt_regs`) and the child's pid from the new task. See [10_probes_common.md](10_probes_common.md) for code generation and the constant-size rule.

## Workflow

### Modes

`New` loads the object, applies capacity overrides, and sets `config_map` to 1 when `PIDFilter > 0` or `DeferRootPID` is set. With `PIDFilter`, it also writes `root_pid_map` and seeds the root into `tracked_pids` as `{is_shell: 1, is_toplevel: 1}`. `SetRootPID(pid)` does the same later, records the pid in `cfg.PIDFilter` and clears `CommandFilter`. With `config_map` at 0 the probe is host-wide: every exec on the host is recorded and `handle_fork` does nothing.

### Kernel side

Every hook is a raw tracepoint (P-32). The syscall hooks sit behind `trace_sys_enter` on `sys_enter`, which fires for every syscall on the host: it switches on the syscall number first (x86_64's: `execve` 59, `exit_group` 231, `execveat` 322) and returns for any other, then skips a 32-bit syscall (`TS_COMPAT` in `thread_info.status`), as the per-syscall tracepoints did. It handles `exit_group` itself; for an exec it returns for an untracked tgid in filtered mode and tail-calls `handle_execve` or `handle_execveat` through `sys_enter_progs`, which `New` fills before it attaches anything. A tail call that fails (an empty slot) counts in `drop_count`. The exec programs read their arguments from the saved user registers by x86_64's syscall convention (`rdi`, `rsi`, `rdx`). `record_exec` is too large to inline into the dispatcher twice, hence the tail calls. The perf-event syscall tracepoints were dropped because on Linux 7.0 `sys_enter_execve` ran its program for only some execs, with no count of the others (P-32 has the measurement and what the kernel source shows).

1. `handle_fork` (filtered mode only) ignores `CLONE_THREAD` clones, reading the clone flags and the new task from the tracepoint's arguments (`task_newtask(task, clone_flags)`; the child's pid is `task->pid` through CO-RE). If the parent tgid is tracked, it emits a `KIND_FORK` record with `pid` = child and `ppid` = parent, then inserts the child into `tracked_pids`. The child's `is_toplevel` is 1 only when the parent is both a shell and top-level.
2. `handle_execve` and `handle_execveat` run at syscall entry, so they record every attempt, including execs that then fail. An `execveat` with an empty pathname and `AT_EMPTY_PATH` execs the descriptor itself (glibc's `fexecve`): there is no path, and the filename is recorded as `(fexecve)` (P-21); an empty pathname without the flag, which fails, and a pathname whose first byte cannot be read are recorded the same way. With a pathname the kernel looks it up whatever the flags, so it is recorded as given, also with `AT_EMPTY_PATH` (`TestObserver_ExecveatWithAPathNamesIt`); one relative to a directory descriptor stays unresolved. Both share `record_exec`, which reads any other filename into a 256-byte buffer with `bpf_probe_read_user_str`, sets `ppid` from `real_parent->tgid` via CO-RE, `tid` from the current thread, and stamps `bpf_ktime_get_ns()`. In filtered mode it returns early for an untracked tgid; for a tracked non-root process it re-evaluates `is_shell` by comparing the filename with eight fixed shell paths (`/bin/sh`, `/usr/bin/sh`, and the same for bash, dash and zsh). It copies up to 64 argv strings into the args area, stopping at 128 KiB, and sets `args_truncated` when a string did not fit, the strings ran past 128 KiB, an argument followed when they filled it exactly, there were more than 64 arguments, or the filename was longer than 255 bytes. A string read that fills its buffer returns the same length whether the string fit with its NUL or was cut, so the program then reads the buffer's last byte from user memory: a NUL there means the string fit. The decision fails safe: the flag stays clear only when every read succeeded and the record provably holds the whole filename and argv up to its terminating NULL pointer. A failed read of the filename, of an argv pointer, of an argv string, of the byte that proves a fit, or of the pointer that would follow a full area or the 64th argument sets it, because these reads cannot fault a page in and fail on a valid argv whose page is not present. A failure used to end the argv loop as if argv had ended, so a command line one byte over the area was recorded unflagged on CI; a failed read is the only path that leaves the flag clear at that size (**Unverified**: the record's length was not logged, and the repeated tests now log every flagged record's length). The tests run each boundary case five times and require that no unflagged record differs from the command line (`TestObserver_CommandLineOfExactly128KiBIsWhole`, `TestObserver_ProgramPathOf255BytesIsWhole`). It outputs the record to the ring buffer; it does not touch `execs`, since the attempt may fail.
3. `handle_exec_ok` runs on `sched_process_exec`, which fires only for an exec that succeeded, after the kernel replaced the image (P-31). In filtered mode it returns for an untracked tgid. It builds a header with the tgid, `ppid` from `real_parent->tgid`, `is_toplevel`, a fresh timestamp, and `tid` set to the tracepoint's `old_pid` (its second argument): a non-leader thread that execs takes the leader's pid, so `old_pid` is the thread that made the attempt. It stores the header in `execs` keyed by tgid, replacing an earlier image's, and outputs it as a `KIND_EXEC_OK` record. A process whose exec attempts all failed therefore has no `execs` entry.
4. The dispatcher, on `exit_group`, stores the low 8 bits of the `exit_group` argument as the exit code in the tgid's `execs` header and sets `has_exit_code`. That is the status the parent's `wait` reads and a shell or a harness reports: `_exit(263)` is 7 and `_exit(-1)` is 255 (`TestObserver_ExitCodeIsTheWaitStatus`).
5. `handle_exit` acts only when the exiting thread is the last of its process: it reads `signal->live` through CO-RE, which `do_exit` decrements before this tracepoint (**Reported**, `kernel/exit.c` at v6.17), and returns unless it is zero. A leader that exits first (`pthread_exit`, a raw `exit`) or that another thread's exec replaces therefore does not end the process: it stays tracked, its later children are in the tree, and its exit record carries the last thread's exit and code (`TestObserver_ProcessOutlivesItsLeaderThread`). In filtered mode it first removes the tgid from `tracked_pids`, so a process that never exec'd leaves the set too (`TestObserver_ProcessThatNeverExecsLeavesTheTrackedSet`). If the tgid has an `execs` entry, it deletes the entry and, if that delete succeeded, outputs the header with the kind `KIND_EXIT` and a fresh timestamp; two threads that exit at once can both read zero, and only one of them deletes. The command line is not in the kernel's copy: keeping it per process would preallocate a gigabyte, so userspace joins the exit to the exec it read.

### Userspace side

`readLoop` reads the ring buffer and decodes the header with `binary.NativeEndian`.

1. A record whose pid equals `cfg.PIDFilter` is dropped: the root is the controller, not an agent action. This covers the root's own exec, which can reach the ring buffer before `SetRootPID` takes effect.
2. A fork record becomes `process_fork` with `Target` = the child pid as a decimal string, `PID` and `PPID`. It is skipped when `CommandFilter` is set.
3. An exec record becomes `process_exec`. `commandLine` builds the target from the filename recorded at syscall entry (the literal `(fexecve)` for an exec through a descriptor) followed by `argv[1:]`; `argv[0]` is dropped because the caller controls it. Only when the filename is empty does it fall back to `argv[0]`. The `joiner` remembers the target and the truncation flag as the latest attempt of the thread `tid`, before any filter. A record with an empty command line is dropped (and forgets the thread's attempt), and `CommandFilter` drops non-matching prefixes.
4. An exec-success record emits no event. The `joiner` makes the latest attempt of its `tid` the image of its tgid, replacing an earlier one; a success whose attempt it never read (a ring drop, counted) clears the image instead. A failed attempt has no success record and changes nothing (`TestJoiner_ExitNamesTheLastImageThatTookEffect`).
5. An exit record becomes `process_exit` with the target and flag of its tgid's image, the last exec that took effect, which are then forgotten (P-31). A process that tried a missing binary and then exec'd another exits under the other (`TestObserver_FailedExecDoesNotNameTheExit`); one that exec'd twice exits under its second program (`TestObserver_ProcessThatExecsTwiceExitsAsItsLastImage`); a non-leader thread's exec names the exit (`TestObserver_ExecByANonLeaderThreadNamesTheExit`). An exit with no known image (the exec or its success record lost to a ring drop, counted by `drop_count`) is not emitted.
6. The event carries `PID`, `PPID`, `TargetTruncated`, `IsTopLevel` (legacy) and, for an exit with `has_exit_code`, `ExitCode`.
7. The event is sent without blocking; a full channel increments `Dropped`.

`Stop` detaches the hooks first, then flushes the ring buffer reader: `readLoop` then reads with a deadline of now, gets every record already committed, and returns at the first empty read (`drainRead`, as N-32 does for the net probe). `Stop` waits for it, snapshots the three kernel counters, closes the reader and the maps, and closes the events channel. Detaching a raw tracepoint does not wait for a grace period, unlike the perf-event tracepoints the probe used before, which took about 60 ms each (N-32).

## Guarantees and loss accounting

The target's first token is the path the kernel was asked to execute (or `(fexecve)` when it was given a descriptor), not `argv[0]`, so a process cannot rename itself in the ground truth (`TestObserver_ResistsArgv0Spoofing`). Every tracked process appears through a fork record even if it never execs, which is what lets a subshell's file activity be attributed (`TestObserver_ForkRecordsPlaceProcessesThatNeverExec`). Threads are never inserted into `tracked_pids` (`TestObserver_ThreadsAreNotTracked`).

| Counter | Incremented when | Coverage field |
|---|---|---|
| `drop_count` | `bpf_ringbuf_output` fails for an exec, exec-success, exit or fork record, or the dispatcher's tail call to an exec program fails | `RingbufDrops` |
| `untracked_count` | inserting a child into `tracked_pids` fails | `UntrackedChildren` |
| `state_lost_count` | storing a successful exec in `execs` fails, so its exit record will be missing | `StateMapFull` |
| `Dropped` (userspace) | the events channel is full | `ChannelDrops` |

All four are event loss ([10_probes_common.md](10_probes_common.md#probecoverage)). Tests force each kernel counter through a capacity override (`TestObserver_CountsRingbufDrops`, `TestObserver_CountsUntrackedChildren`, `TestObserver_CountsStateMapFull`) and check that the tracked-set and state-map counters stay zero when the map fits. `TestObserver_EveryExecAttemptIsRecorded` runs 200 `/bin/true` children and 50 failed attempts under a tracked shell and requires one exec record per attempt, one exit per successful exec and no loss counted, stopping the probe as soon as the shell has exited; `TestHooks_EveryProgramIsARawTracepointAndIsWired` checks, without root, that every program is a raw tracepoint that `New` attaches or the dispatcher tail-calls.

## Known limits

- A process that never execs produces no `process_exit`, because exit records are copies of an `execs` entry; nor does one whose exec attempts all failed, such as the child of a spawn helper (Go, Python, libuv) that exits with a code of its own after a failed exec (P-31).
- The exit names the last exec that took effect, so a process that exec'd twice (a shell that execs its last simple command) exits under its second program, while the verifier aligns its first exec with its exit. Under `Generic` and `simagent`, which claim exits, an exit claim naming the command the agent ran then reads as a substitution of the target; the real adapters do not claim exits (I-15).
- A lost exec-success record leaves the exit joined to the image before it, or to none; the loss is counted in `drop_count`.
- A process killed by a signal never calls `exit_group`, so its exit has no `ExitCode`; nor does one whose last thread ends with a plain `exit` rather than `exit_group`.
- Filename and argv are read from user memory at syscall entry, so another thread can change them before the kernel copies them.
- An exec through a descriptor names no program: its target is `(fexecve)` followed by the arguments, so a claim that names the program reads as a substitution unless the adapter rewrites one side (P-21, `TestObserver_ExecThroughADescriptorIsRecorded`). An `execveat` pathname relative to a directory descriptor is recorded unresolved, and reads like a pathname relative to the working directory, which the probe does not capture either.
- argv is kept up to 64 arguments and 128 KiB in all, and the filename up to 255 bytes; beyond that the record is cut and `TargetTruncated` says so, and the verifier pairs the cut target by prefix as unverified (V-26). A record the probe could not read to its end is flagged the same way, so an honest command line can read as cut, which costs only the prefix pairing. Linux allows one argument of 128 KiB, and the shell's own arguments share the 128 KiB area, so a harness's single-string command fits unless it nears that size (`TestObserver_LongCommandLineIsRecordedWhole`, `TestObserver_OverlongCommandLineIsFlagged`).
- The probe captures no working directory, environment or stdin, so relative paths in argv are unresolved and a script fed through a pipe or heredoc is invisible.
- In host-wide mode no fork records are emitted, so the forest cannot place processes that never exec.
- With `cmd/watch --root-pid`, the root pid is inserted into a process already running, so a fork before `SetRootPID` is untracked and uncounted. An agent `cmd/watch` launches is registered before it execs (P-23, [10_probes_common.md](10_probes_common.md#how-cmdwatch-builds-and-starts-probes)).
- The shell test is a comparison against eight fixed paths and only feeds the legacy `IsTopLevel` field. It runs at the attempt, so a failed exec of a shell path changes `is_shell` too.
- `PPID` is the parent at exec time; a later reparenting is not reflected in the exit record.
- A 32-bit (ia32) syscall is skipped, as the per-syscall tracepoints skipped it on x86_64: a 32-bit process's exec attempts have no record, so its exec's success record finds no attempt and its exit is not emitted, and its `exit_group` code is not recorded. A 64-bit process that execs a 32-bit program is recorded, since the exec is a 64-bit syscall. The syscall numbers and argument registers are x86_64's.
- The dispatcher runs for every syscall of every process on the host, adding a program call and a switch to each; its cost is not measured (**Unverified**).
- A hook still running on another CPU when `Stop` detaches it can commit a record after the drain has ended; that record is lost uncounted. The window is the run time of one program.
- A raw tracepoint program that the kernel does not run because the same program is already running on that CPU (a nested call, in practice only from an NMI) increments the program's own `recursion_misses`, which the probe does not read.
