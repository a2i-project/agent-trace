# Gemini Repository Instructions

Read `AGENTS.md` first. This file only adds Gemini-specific commit metadata and exists so a Gemini harness that loads model-specific docs first still picks up the shared workflow.

## Git Commit Standard

All commits generated by agents MUST follow this exact template, dynamically inserting the actual model name used during the session:

```
[agy] <type>: <short description>

- <detail 1>
- <detail 2>

Docs: updated | none (<why no documented behaviour changed>)
Implements: <decision IDs built by this commit, if any>
Closes-Todo: <todo IDs finished by this commit, if any>

Co-Authored-By: <Model Name> <noreply@google.com>
Harness: Antigravity CLI
Model: <model name>
```

Fill in the model the session actually runs (for example `Gemini 3.1 Pro (High)`). The tag `[agy]` names the Antigravity harness. The `Co-Authored-By` line is what GitHub parses for contributor attribution; `Harness` and `Model` are for traceability.

The `Docs:` trailer is mandatory and checked by CI and the `commit-msg` hook; `Implements:` and `Closes-Todo:` are written only when they apply (rules in `AGENTS.md`, "Documentation contract"). Remove the lines that do not apply; keep `Docs:`.
